# 上传 Git 与发布网站

## 推荐：GitHub Desktop

1. 在 GitHub 新建空仓库，例如 character-workshop。不要自动生成 README，以免首次推送冲突。
2. 在本项目目录运行 `git init -b main`，然后用 GitHub Desktop 的 File → Add Local Repository 选择此目录。
3. 检查变更并提交，在 Repository Settings 设置新仓库的远程地址，再 Publish / Push。
4. 在 GitHub 仓库 Settings → Pages，把 Source 设为 GitHub Actions。
5. 在 Actions 中打开 Deploy static website to GitHub Pages，必要时点 Run workflow。
6. 成功后从 Settings → Pages 或部署任务里的链接访问网站。通常为 https://你的用户名.github.io/仓库名/ 。

## Git 命令方式

在包含 public、docs、.github 的仓库根目录执行（把 URL 替换为自己的真实仓库）：

```sh
git init -b main
git add .
git commit -m "Prepare character workshop website"
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

如 Git 提示身份未设置，按自己的信息配置 user.name 和 user.email，再提交。登录使用 Git Credential Manager 或 GitHub Desktop，不把令牌写进源码。
若仓库已经初始化，不必重复 init；已有 origin 时检查地址再设置，不盲目覆盖远程。不要强制推送。
Pages 可能受仓库可见性和账号套餐限制，按 GitHub 当前界面提示选择。此包尚未连接仓库、推送或上线。

## 后续更新

修改 public 下文件 → 本地预览 → git add / commit / push；main 分支更新会触发部署。
模型保持原修复文件，仅约 45.6 MB，不需要 LFS，但不能用 GitHub 网页直接上传这一大文件。
替换模型时同步 model-info.js 中统计信息；不要上传原离线版 model-data.js，避免额外约 60 MB Base64。

## 其他静态托管

构建命令留空，发布目录设为 public，无服务端和环境变量。使用根路径或仓库子路径均可，资源路径为相对路径。无需 SPA rewrite，阶段路由使用 #hash。

## 故障排查

- 模型加载失败：检查 public/models/bridgerton-003.glb 已提交，文件是真实 GLB 而非 LFS 指针；查看浏览器网络请求。
- 页面 404：检查 Pages Source 为 GitHub Actions、分支为 main、Actions 成功。
- 图片缺失：提交整个 public/assets，注意路径大小写；不要仅上传 index.html。
- 看到旧页面：刷新或清除该站缓存。
